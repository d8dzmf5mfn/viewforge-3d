# ViewForge 3D Local 下一代架构

[English](NEXT_LOCAL_ARCHITECTURE.md) | [简体中文](NEXT_LOCAL_ARCHITECTURE.zh-CN.md)

本计划只适用于 `viewforge-3d-local`，不会修改 ChatGPT/Tunnel 版本及其 release 线。

## 设计边界

模型负责给出语义意图、证据角色、有界参数、约束和明确的构造策略；本地确定性代码负责几何、
拓扑、序列化、验证和产物溯源。ViewForge Asset IR 是二者之间的契约，GLB 是经过验证的部署
输出，不是模型的推理语言。

证据权限按以下顺序区分：

1. `observed`：用户提供的视图、测量、关键点或遮罩。
2. `inferred`：由观测证据和显式先验推导出的几何。
3. `generated`：隐藏视角或补全提示的假设，不能与真实观测同权。

## 能力成熟度与验收状态

能力同时报告实现状态和成熟度：`planned`、`experimental`、`validated`、`trusted`。即使已安装，
某条路线也可能只能输出预览。

| 能力 | 当前状态 | 输出边界 |
| --- | --- | --- |
| 声明式基础体编译器 | validated、已实现 | IR 验证后可编译 |
| 六视图 visual hull | experimental、已实现 | 仅预览 |
| 参数化模板拟合 | planned | 未实现前关闭失败 |
| 学习式多视图补全 | planned | 未实现前关闭失败 |
| 拓扑保持平滑 | validated、已实现 | 只做打磨，不能补造缺失证据 |

IR 验证通过只代表契约可接受；编译成功只代表确定性后端完成。两者都不等于形状已经验收。
编译结果保持 `needs_model_verification`，直到规范视角渲染、必要的参考图比较和用户确认全部完成。

## 六视图重建顺序

下一阶段的六视图后端应拟合稳定的标准拓扑，而不是把 visual hull 直接升级为最终几何：

1. 验证六个视角、图像完整性、主体一致性、尺度假设、遮罩和相机信息；主体混杂或证据冲突
   未解决时直接拒绝。
2. 选择明确的类别模板，模板固定拓扑、关键点、对称区域和受保护特征。人脸、人体和通用物体
   必须使用不同模板。
3. 依据真实轮廓和关键点联合拟合相机与形状参数；生成或推断证据的权重必须低于真实观测，
   并把权重写入溯源记录。
4. 进行有界、拓扑保持的表面打磨；记录位移、受保护顶点、边界变化、UV/材质变化和体积差异。
5. 验证有限且非空的几何、拓扑、GLB 解析、六张对齐源视图、规范视图及参考差异；失败或待定
   门禁必须明确保留。
6. 输出不可变的 Blend、GLB、QA 和溯源产物。超出预览状态必须由用户明确确认。

## 本地里程碑

- 里程碑 1——已完成：类型化 Asset IR、能力注册表、关闭失败路由、确定性基础体编译、溯源报告
  和强制后置门禁。
- 里程碑 2——下一步：类别化参数模板注册表，以及第一个由六张真实视图和关键点驱动的人脸模板
  拟合器。
- 里程碑 3——后续：可选的本地学习式补全适配器，记录模型/版本哈希，并标记所有生成证据。
- 里程碑 4——后续：把失败指标转成有界 IR 参数调整的修复循环，同时保留原始证据和每次编译版本。

所有阶段都保持本地 stdio，使用仓库虚拟环境，只保存私有本地路径，不需要 Tunnel 或 OpenAI
API Key。
